## Talking points

1. **What happens today.** SFFD engine companies inspect hydrants and send an annual "Items Needing Attention" report (the FY22-23 one lists hydrants and cisterns). Issues are typed as free text, so the same problem is written many ways, there's no map, and SFPUC sees it once a year.
2. **What the MVP changes.** A crew taps the hydrant on a map, fills in a short form, and the inspection is saved to SFPUC's portal straight away, tied to that hydrant. Problems are picked from a list instead of typed, and the app works out low pressure and "needs follow-up" by itself.
3. **One table, two apps.** We built the same form in Field Maps and in Survey123 so staff can compare them. Both write to one inspections table, so nothing is lost whichever one we pick.
4. **Status at a glance.** Gray means never inspected, green means OK, yellow means due, red means SFPUC needs to act.
5. **Crews can't change hydrants.** Crews only add inspections and can fix only their own. The GIS team keeps the hydrant data.
6. **Sign-in is required for both apps.** The portal doesn't allow anonymous access, so every crew member needs an account either way. This used to look like a Survey123 advantage; it isn't one here.
7. **It's a demo, not the final app.** 21 sample hydrants around Engine 1, made-up inspections, and a form we'll rebuild once we choose the app.

## Not in this demo

Say these up front so they don't come up as surprises:

- **Field Maps offline.** Taking the map offline waits on an offline-ready basemap (see [Offline basemap](reference/offline-basemap.md)). Survey123 already works with no signal: forms wait in the Outbox and send later.
- **The form gets rebuilt after the demo.** This is the MVP form. In the real build, for example, Remarks moves to an always-shown **Comments** field at the end of the form.
- **Only low-pressure hydrants.** AWSS (high-pressure) hydrants and cisterns come later.
- **Sample hydrants.** 21 hydrants near Engine 1 with estimated locations. Real hydrants will come from the Utility Network or Maximo.
- **No dashboard yet.** A supervisor dashboard (low-pressure list, follow-up count, inspections by engine company) can be built on the same table.
- **No Maximo link yet.** Turning follow-ups into Maximo work orders through FME Flow is a later phase.
- **The inspector list needs cleanup.** Some names in the list picked up text from the report (for example "Likely Painted Over Sansoni,V"). It gets cleaned before any pilot.

## Decisions to ask for

For each one, give the recommendation, then ask. Write down the answer and an owner.

**1. Which app do we take forward: Field Maps alone, or Field Maps plus Survey123?**

- *Field Maps alone:* one app, one sign-in, full offline map once the basemap is set up, crews can fix their own mistakes.
- *Field Maps plus Survey123:* crews still open Field Maps to find the hydrant, then jump to Survey123 to fill in the form. Survey123 adds a required photo for follow-ups, an inspector list filtered by engine company, and offline forms today.
- **Recommendation:** Field Maps alone. With no anonymous access, Survey123's main advantage is gone, and it means two apps for crews. Keep Survey123 in mind for printable reports later.
- **Or:** run the SFFD pilot with both apps as planned in [step 8](setup/08-pilot.md) and let crews decide.

**2. Who owns the SFFD pilot?**

- We need a **pilot lead** (SFPUC, owns the plan and the recommendation) and an **SFFD contact** (a battalion or station officer who picks 6 to 8 testers and books station time). See [Roles](setup/08-pilot.md#roles).
- If we picked one app in decision 1, the pilot can be shorter: one app, one session per tester.

**3. Who sets up accounts for SFFD crews?**

- Every tester, and later every crew member, needs a portal account that can edit. Ask who requests them, which user type and license they need (check with the portal admin), and whether accounts are per person (recommended, so inspections show who did them) or shared per station.

**4. What comes next, and in what order?** Suggested order:

1. Offline basemap for Field Maps (owner?)
2. Rebuild the form in the chosen app, with the cleaned inspector list
3. SFFD pilot
4. Real hydrant data from the Utility Network or Maximo
5. Supervisor dashboard
6. AWSS hydrants and cisterns
7. Maximo work orders through FME Flow

Ask for a target date for the pilot and whether this should replace the next annual report.

## Questions they may ask

| Question | Answer |
|---|---|
| Can crews use it without an SFPUC account? | No. The portal doesn't allow anonymous access, so both apps need a sign-in |
| Does it work with no signal? | Survey123 does today: forms wait and send later. Field Maps will, once the offline basemap is set up |
| Where is the data stored? | In one hosted layer on SFPUC's portal (gis.sfpuc.org/portal). Crews reach it through a view that only lets them add inspections and edit their own |
| Can a crew fix a mistake? | In Field Maps, yes, on their own inspections. In Survey123, not once it's sent |
| Can they delete an inspection? | No. Only the GIS team can |
| Can we still get a report like the annual one? | Yes. The table can be exported, and a dashboard can show the same list live |
| Can crews add or move hydrants? | No. Hydrants are read-only for crews. The GIS team edits them, and later they'll come from the Utility Network or Maximo |
| How long does an inspection take? | Time it in the dry run and quote that. The pilot measures it properly |
| What does it cost? | No new software: both apps come with ArcGIS Enterprise. The cost is a user type for each crew account; confirm with the portal admin |

### Clean up after the demo

This deletes every inspection whose Remarks starts with `TEST.`, and nothing else. The demo data stays.

1. In ArcGIS Pro, sign in to the portal as the owner of the source layer.
2. Copy the **source** layer's service URL, ending in `/FeatureServer`. Not the field view's.
3. Open **Python Command Prompt** (Windows Start > ArcGIS > Python Command Prompt) and run this, with your URL in place of `<source service URL>`:

    ```
    propy "C:\hydrant-mvp\load_demo_inspections.py" --service <source service URL> --remove-tests
    ```

4. It prints `Removed 2 test inspections` (or more, if you added others while testing).

Full steps, including what to do if it can't open the table: [Clean up test records](setup/07-test.md#clean-up-test-records).
